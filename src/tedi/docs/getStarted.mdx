# Get started with @tedi-design-system/react

### Installation

```bash
npm install @tedi-design-system/react
```

Supported React versions are **React 18.3.1 and React 19**. See
[Supported versions](https://github.com/TEDI-Design-System/general/wiki/Supported-versions) for the
support policy.

`dayjs` is a peer dependency and must be installed by the application — see the Day.js section below.

### Importing components

Components are published as two separate entry points:

```tsx
import { Button } from '@tedi-design-system/react/tedi';
import { Card } from '@tedi-design-system/react/community';
```

**TEDI-Ready** components are maintained by the TEDI team and meet the full
[Definition of Done](https://github.com/TEDI-Design-System/general/wiki/Definition-of-Done).
**Community** components are contributed and held to a lighter standard. Prefer a TEDI-Ready
component where one exists.

### Application setup

Import the styles once at the root of your application and wrap it in the provider chain:

```tsx
import '@tedi-design-system/react/index.css';

import { AccessibilityProvider, LabelProvider, StyleProvider, ThemeProvider } from '@tedi-design-system/react/tedi';

<ThemeProvider>
  <LabelProvider>
    <StyleProvider>
      <AccessibilityProvider>
        <YourApp />
      </AccessibilityProvider>
    </StyleProvider>
  </LabelProvider>
</ThemeProvider>;
```

Each provider does one thing: `ThemeProvider` applies the theme class to the `html` element,
`StyleProvider` imports the library's global SCSS, `LabelProvider` supplies the label context
components read, and `AccessibilityProvider` initializes `what-input` and renders the live region
that loaders announce through.

#### ThemeProvider

Provides the active theme, applied as a `.tedi-theme--*` class on the `html` element. Dark mode is a
semantic-token override applied through this provider.

Only `default` and `dark` ship with the library's CSS. Any other theme name is a custom theme and is
**not bundled** — you generate it from your project's Figma variables and include its stylesheet
yourself. The prop is not validated, so an unknown name fails silently. See
[Custom theming](/docs/documentation-custom-theming--docs).

#### LabelProvider

Provides the labels components use, mostly for accessibility. Every application should be wrapped
with it. See all labels under [Documentation/Labels](/docs/documentation-labels--docs), and the
component documentation under [components](/docs/components-labelprovider--docs).

#### StyleProvider

Provides the global styles the library depends on.

#### AccessibilityProvider

Provides global accessibility functionality — Skeleton accessibility texts, and initialising the
`what-input` library.

The community `Layout` component renders `AccessibilityProvider` internally, so applications built
on `Layout` do not need to add it. `Layout` is a **community** component and is not required for
consuming TEDI, so an application built on TEDI-Ready components alone must include
`AccessibilityProvider` in its own provider chain, as shown above.

### Day.js

Some components depend on Day.js and MUI X. Day.js must be an application dependency, so it is
recommended to use it for handling dates.

The `'en'` locale has a modified rule that sets `weekStart` to Monday. Overriding this rule is
currently not supported — if you need to, please reach out on Slack.

### Server-side rendering

When using SSR you can pass the `defaultServerBreakpoint` prop to every component that uses
[BreakpointProps](/docs/helpers-usebreakpointprops--usebreakpointprops). This lets you declare which
breakpoint the component should render at on the server, avoiding layout shifts.
