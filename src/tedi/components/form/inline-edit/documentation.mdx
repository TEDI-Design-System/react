# Render props & hook

How to wire a control into `InlineEdit`, and how to build your own markup with the headless `useInlineEdit` hook.

Forward `size` to the control so a small field opens a small editor:

```tsx
{
  ({ value, onChange, size }) => (
    <TextField id="name" label="Nimi" hideLabel value={value} onChange={onChange} size={size} />
  );
}
```

Controls that don't use `value` / `onChange` need a one-line adapter: `DateField` takes `selected` / `onSelect`, and
`Toggle` takes `checked`.

## Committing on pick

For **single-action** controls — a single-select `Select`, `Radio.Group`, or `Toggle` — commit as soon as the user
makes a selection rather than waiting for blur. A multi-select `Select` or `Checkbox.Group` should _not_ do this: call
`onChange` only and let the commit happen on blur, otherwise the field closes after the first pick.

```tsx
<InlineEdit<ISelectOption | null>
  label="Riik"
  value={country}
  onChange={setCountry}
  renderValue={(v) => (v ? (v.label as string) : '-')}
>
  {({ value, onChange, commit }) => (
    <Select
      id="country"
      label="Riik"
      hideLabel
      options={countryOptions}
      value={value}
      onChange={(next) => {
        onChange(next as ISelectOption | null);
        commit();
      }}
    />
  )}
</InlineEdit>
```

## `useInlineEdit` hook

When you need full control of the markup, use the headless `useInlineEdit` hook instead of the `InlineEdit` wrapper. It
manages the read/committed value and the edit draft, with `edit` / `commit` / `cancel` transitions, and supports both
controlled and uncontrolled use.

```tsx
const { isEditing, edit, commit, cancel, committedValue, value, onChange } = useInlineEdit<string>({
  value,
  onChange: setValue,
});
```
